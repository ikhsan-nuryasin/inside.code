# Student Hub v1.8.0 — Security Hardening

## Tujuan

Release ini menambahkan beberapa lapisan keamanan pada autentikasi dan deployment. CAPTCHA membantu mengurangi bot/credential abuse pada endpoint autentikasi; proteksi volumetric DDoS tetap membutuhkan kontrol di provider/edge (mis. CDN/WAF).

## 1. CAPTCHA / Cloudflare Turnstile

Frontend memakai Cloudflare Turnstile pada:

- Sign in
- Sign up
- Password recovery

Aktifkan di Supabase Dashboard:

`Authentication → Settings → Bot and Abuse Protection → CAPTCHA`

Pilih provider Turnstile dan masukkan **secret key** Turnstile ke konfigurasi Supabase. Secret key tidak boleh masuk ke source frontend.

Frontend environment:

```env
VITE_CAPTCHA_REQUIRED=true
VITE_TURNSTILE_SITE_KEY=YOUR_TURNSTILE_SITE_KEY
```

Site key boleh ada di browser. Secret key tetap server-side/Supabase.

## 2. Auth rate limiting

Supabase Auth tetap menjadi rate limiter server-side untuk sign-in/sign-up/recovery. Student Hub menambahkan guard UX lokal untuk menghentikan percobaan berulang pada browser setelah beberapa kegagalan. Guard lokal bukan pengganti rate limit server.

## 3. Login enumeration

Pesan login dibuat generik (`Email atau password salah.`). Alur recovery juga memakai pesan generik sehingga keberadaan email tidak dibocorkan melalui UI.

## 4. Password policy

Akun baru membutuhkan:

- minimal 12 karakter;
- huruf kecil;
- huruf besar;
- angka;
- simbol.

Atur password policy dan leaked-password protection dari Supabase Auth sesuai kemampuan plan/project.

## 5. MFA

Release ini menyediakan TOTP MFA melalui halaman **Pengaturan → Keamanan**. Ketika akun memiliki faktor MFA terverifikasi, aplikasi akan memaksa challenge MFA setelah session AAL1 dan sebelum pengguna masuk ke workspace.

## 6. Session protection

Tersedia:

- auto refresh token;
- persist session;
- global sign out;
- MFA assurance check;
- local cleanup saat logout.

## 7. Hosting security headers

Konfigurasi hosting memasukkan:

- HSTS;
- X-Frame-Options;
- X-Content-Type-Options;
- Referrer-Policy;
- Permissions-Policy;
- Content-Security-Policy.

CSP mengizinkan Supabase dan `challenges.cloudflare.com` untuk Turnstile.

## 8. Secrets

Jangan pernah menaruh:

- Supabase service role key;
- Supabase secret key;
- VAPID private key;
- Turnstile secret key;

di source frontend atau `VITE_*` client environment.

## 9. RLS

RLS tetap merupakan authorization boundary utama untuk data Student Hub. Frontend guard tidak boleh dianggap sebagai security boundary.

## 10. Deployment checklist

```text
[ ] HTTPS aktif
[ ] Supabase CAPTCHA enabled
[ ] Turnstile secret di Supabase
[ ] VITE_CAPTCHA_REQUIRED=true
[ ] VITE_TURNSTILE_SITE_KEY terisi
[ ] Supabase publishable key saja di browser
[ ] MFA test berhasil
[ ] Login wrong-password test
[ ] Recovery test
[ ] Rate-limit/abuse test
[ ] Security headers test
[ ] RLS test
[ ] Push notification test
[ ] npm run typecheck
[ ] npm run build
```


## 11. DDoS vs CAPTCHA

CAPTCHA bukan pengganti DDoS mitigation jaringan. CAPTCHA terutama mengurangi automated/bot abuse pada form autentikasi. Untuk serangan volumetric atau traffic L3/L4/L7 yang besar, gunakan edge/CDN/WAF yang menyediakan DDoS mitigation dan rate limiting.

Untuk domain sendiri, Cloudflare dapat ditempatkan di depan hosting sebagai reverse proxy/CDN. Aktifkan managed DDoS rules, WAF/rate limiting sesuai kebutuhan, dan jangan mengekspos origin secara langsung. Vercel juga menyediakan automatic DDoS mitigation dan opsi WAF/rate limiting.

## 12. Turnstile server-side validation

Untuk flow autentikasi, Supabase Auth menerima `captchaToken` dan melakukan validasi sesuai integrasi CAPTCHA project. Untuk Edge Function/custom endpoint di luar Auth, validasi Turnstile harus dilakukan server-side menggunakan Siteverify; secret key tidak boleh berada di browser.
