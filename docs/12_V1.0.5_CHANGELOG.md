# Student Hub v1.0.5 Changelog

## User-requested changes

### Class mode
Every class now has exactly two supported modes:
- `offline` — physical/tatap muka.
- `online` — remote/daring.

The restriction is enforced in PostgreSQL through the `class_delivery_mode` enum. The web UI only exposes these two values when creating or editing a class.

### Timetable from supplied image
The weekly timetable in `docs/assets/jadwal-matakuliah-sumber.png` has been transcribed into the application. It contains 8 weekly schedule rows from Monday through Thursday.

The application preserves:
- day
- start/end time
- course code
- course name
- lecturer code 1
- lecturer code 2 (nullable because the source image shows `-`)
- SKS
- practical group
- room for offline classes
- optional meeting URL for online classes

### Import workflow
A class admin can click `Muat jadwal dari gambar` on the class Schedule tab. The action is confirmed before execution.

The server uses `apply_schedule_template(class_id)` and upserts the 8 template rows by stable course code and schedule slot. Repeating the action does not create duplicates and does not delete unrelated custom schedules.

## Security considerations
Class creation uses the server-side `create_class(...)` SECURITY DEFINER RPC. The previous direct client INSERT policy is removed in migration 009, preventing clients from bypassing the validated class-creation flow.

## Offline considerations
The timetable and class mode are cacheable data and remain readable offline after synchronization. Switching to online mode causes the schedule UI to prefer a meeting URL; switching to offline mode causes it to display the physical room.
