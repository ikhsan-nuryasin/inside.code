STUDENT HUB V1.0.8 — AI CODING MASTER PROMPT

You are implementing Student Hub v1.0.8 Phase 1 and must preserve the current product freeze. Treat `docs/00_CURRENT_SOURCE_OF_TRUTH.md` as authoritative. Do not resurrect features removed below.

PRODUCT:
- Student-only class companion PWA.
- React + TypeScript + Vite + Supabase + IndexedDB + PWA.
- Android access is through installable PWA. Do not add Flutter.
- No lecturer role.
- No official campus attendance.

REMOVED FEATURES:
- Create class from client.
- Join class from client.
- Public class member directory.

CLASS MODE:
- Exactly `offline` or `online`.

OFFICERS:
- ketua, wakil_ketua, sekretaris, bendahara.
- Position assignments are server validated.
- Leadership manages officers.
- Secretary manages announcements, schedules, materials, documentation, and polls.
- Treasurer manages cash, dues, payments, and financial evidence.
- Leadership manages class settings, tasks, groups, and all officer-level features.
- Ordinary member receives ordinary student features and own personal data only.

GROUP LEADER:
- Separate group-level role.
- Can be selected by wheel/random or manually.
- Server must validate group membership.

ARCHITECTURE:
- Supabase Auth for identity.
- PostgreSQL for authoritative data.
- Supabase Storage for files.
- IndexedDB for offline client state.
- Sync queue for offline mutations.
- RLS is mandatory and is the real authorization boundary.

OFFLINE RULES:
- Cache data locally.
- Queue writes while offline.
- Retry only network/transient server failures.
- Do not delete queue items on validation/RLS/conflict failures.
- Store failed/conflict state and error message.
- Use retry backoff.

SECURITY RULES:
- Never expose service-role/secret key.
- Do not trust client role checks.
- Prefer RPC for officer assignment and sensitive workflows.
- Prevent last-admin/last-leadership removal where required.
- Validate file size, MIME type, ownership, and class membership.

UX RULES:
- Mobile-first responsive UI.
- Do not use a giant tab bar containing every feature.
- Group features by Overview, Learning, Community, Class Administration, Files, System.
- Show loading, empty, error, offline, and syncing states.
- Explain offline data freshness to the user.

DO NOT:
- add Google Sheets;
- add Google Drive;
- add Laravel;
- add MySQL local;
- add Flutter;
- weaken RLS to fix a UI error;
- invent a lecturer/admin portal;
- claim full offline support until every promised offline mutation has a queue implementation and conflict policy.


PHASED DELIVERY RULE:
- Phase 1 is authorization/data-integrity hardening.
- Do not mark the whole product production-complete until Phase 2-5 are verified.
- Implement only the current phase when a task explicitly requests staged work.
